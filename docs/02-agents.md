# قرارداد ایجنت‌ها

## A00 — Internal Manager / Orchestrator
مسئول:
- تقسیم کار.
- تعیین اینکه کدام ایجنت مجاز به تولید/استفاده از هر داده است.
- جلوگیری از استفاده از داده stale.
- اجرای verification loop.
- تهیه پاسخ نهایی برای مالک پروژه.
- ثبت رخدادها، خطاها و تغییرات.

ممنوع:
- تولید عدد رتبه قبولی از حافظه.
- تغییر دستی رتبه‌ها بدون Evidence.
- تبدیل اختلاف منابع به یک عدد واحد بدون ثبت uncertainty.

## A01 — Source Sentinel
مسئول پایش مستمر/شبانه‌روزی منابع:
- سازمان سنجش.
- وزارت علوم.
- دفترچه‌ها و اطلاعیه‌های رسمی.
- دانشگاه‌ها.
- منابع رتبه‌بندی معتبر.
- منابع رسمی آمار اشتغال در صورت دسترس.

خروجی:
`source_event`, `document_snapshot`, `changed_fields`, `impact_level`.

سیاست:
هیچ ایجنت تحلیلی مستقیماً crawler خام را مصرف نمی‌کند؛ فقط داده canonicalized و versioned را می‌گیرد.

## A02 — Admission Statistics Agent
مسئول:
- استخراج رتبه‌های قبولی پنج سال اخیر.
- تفکیک سال داده از سال تحصیلی.
- تفکیک منطقه/سهمیه.
- تفکیک روزانه/نوبت دوم/پردیس/سایر دوره‌ها.
- محاسبه بازه، میانه، صدک‌ها و روند.
- اندازه نمونه و پوشش.

خروجی احتمالاتی باید بازه و confidence داشته باشد، نه «قطعیت قبولی».

## A03 — University Academic Quality Agent
مسئول:
- QS / THE / ISC به شکل مستقل.
- رتبه کلی دانشگاه جدا از رتبه موضوعی.
- شاخص‌های پژوهش، آموزش، صنعت و بین‌المللی‌شدن در صورت دسترس.
- سطح برنامه/دانشکده در صورت وجود داده معتبر.

## A04 — Student Life / Housing Agent
مسئول:
- خوابگاه.
- وضعیت ظرفیت/شرایط اسکان.
- فاصله و جابه‌جایی.
- هزینه‌های زندگی در حد داده معتبر.
- امکانات آموزشی/رفاهی.
- وضعیت شهر دانشگاه.

## A05 — Student Satisfaction Agent
مسئول:
- جمع‌آوری نظرسنجی‌ها و بازخوردهای دانشجویی.
- تفکیک رضایت رسمی، پیمایش نمونه‌ای و محتوای کاربرمحور.
- ثبت حجم نمونه، سال و روش جمع‌آوری.
- جلوگیری از تبدیل چند نظر آنلاین به «رضایت دانشجویان» کل دانشگاه.

## A06 — Career Future Agent (اولین ایجنت تخصصی)
مسئول:
- آینده رشته/خانواده رشته.
- نیاز بازار کار در کشورها/مناطق مختلف.
- مسیرهای شغلی دولتی و غیردولتی.
- سازمان‌ها/صنایع قابل ذکر.
- درآمد تقریبی با ذکر کشور، سال، ارز، منبع و نوع شاخص.
- مهارت‌های مورد تقاضا.
- ریسک جایگزینی/تغییر نقش توسط فناوری.
- تحرک بین‌المللی و موانع ورود.

## A07 — Preference / Interest Agent
مسئول تبدیل پاسخ‌های کیفی داوطلب به پارامترهای قابل محاسبه:
- علاقه به رشته.
- علاقه به دانشگاه.
- علاقه به شهر.
- حساسیت به هزینه.
- تحمل فاصله/مهاجرت.
- نوع دوره.
- اولویت بازار کار.
- اهمیت احتمال قبولی.

## A08 — Geography / Eligibility Agent
مسئول:
- بومی‌گزینی و سهمیه‌ها طبق منبع رسمی.
- شرایط قانونی.
- محل دانشگاه/پردیس.
- محدودیت شهر و نوع دوره.
- الزامات خاص رشته.

## A09 — Recommendation Engine
ترجیحاً سرویس deterministic؛ LLM فقط برای تفسیر.
ورودی:
- داوطلب.
- داده canonical.
- خروجی همه ایجنت‌ها.
خروجی:
- مجموعه گزینه‌های واجد شرایط.
- احتمال قبولی.
- utility.
- risk.
- alternatives.

## A10 — Verification / Red-Team Agent
مسئول:
- بررسی خلاف‌فرض‌ها.
- کشف داده stale.
- کشف عدم سازگاری سال/دوره.
- بررسی اختلاف منابع.
- کنترل اینکه هیچ hard constraint نقض نشده باشد.
- تولید `verification_report`.

## A11 — Presentation / Explanation Agent
مسئول:
- زبان فارسی قابل فهم.
- توضیح چرایی پیشنهاد.
- نمایش سطح اعتبار.
- نمایش منابع.
- نمایش موازی‌ها در همان سلول.
نباید رتبه داخلی سیستم را بدون معیار مستند به «واقعیت علمی» تبدیل کند.

## مسیر همکاری
نسخه اول با همین قرارداد قابل ساخت است. در فاز کدنویسی، چند نقش موازی ارزشمند هستند:
1. توسعه‌دهنده backend/data ingestion.
2. توسعه‌دهنده statistical admission engine.
3. توسعه‌دهنده frontend recommendation cells.
4. متخصص data engineering / source monitoring.
5. متخصص QA و آزمون داده.

در این مرحله برای «طرح معماری» نیاز به عضو هوش مصنوعی دیگری نیست؛ هنگام ورود به پیاده‌سازی موازی، این تقسیم کار باید تبدیل به issueهای مستقل GitHub شود.
